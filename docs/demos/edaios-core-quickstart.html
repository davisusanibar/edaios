EDAIOS · CORE PORTABLE

Usar EDAIOS Core y crear un proyecto gobernado

Core proporciona contratos, memoria local, perfiles, Spec Kit y gates. No instala dominios, productos ni runtimes de negocio.

1. Instalar el CLI

cd /ruta/al/repositorio/edaiosv
python3 -m pip install ./core/framework
edaios-core --help
edaios-core memory doctor --root .
El backend de build actual no ofrece instalación editable PEP 660; instala el paquete normalmente (idealmente dentro de un entorno virtual). El entrypoint es edaios_core_harness.cli:main.

2. Crear una feature de Core

Los cambios empiezan por contrato, no por código.

python3 tools/operations/feature_context.py resolve --path-only
python3 tools/validation/spec_kit_gate.py . --feature specs/NNN-nombre
./scripts/test.sh
./scripts/validate.sh
  • Spec: requisitos FR, criterios SC y límites.
  • Plan: Constitution Check y Gate Impact.
  • Tasks: trabajo trazable.
  • Evidence: resultados observados.

3. Crear un proyecto o iniciativa

El proyecto vive fuera de Core y entra mediante un attachment explícito.

edaios-core init --workspace ./mi-proyecto \
  --id iniciativa-demo --namespace demo --owner OWNER \
  --value-owner OWNER --core-version 3.1.0
edaios-core adopt --workspace ./mi-proyecto
edaios-core validate --workspace ./mi-proyecto \
  --profile initiative-adoption
  • Declara initiative id, namespace y owner.
  • Declara autoridad, sensibilidad y PolicyProfile.
  • Fija versión/digest de Core.
  • Mantén sus fuentes en su propio Git.
No copies dominios ni inventes owners o datos institucionales dentro de Core.

4. Memoria local y Engram opcional

edaios-core memory doctor --provider local
edaios-core memory search --query "último cambio" --provider local
edaios-core memory doctor --provider engram
edaios-core memory context --provider engram --project mi-proyecto --scope project

Engram es opt-in y loopback; su runtime se instala fuera de Core. Git, Knowledge Objects y receipts siguen siendo la autoridad. memory context no acepta una consulta de texto: devuelve el contexto agregado del proyecto.

5. Entrega segura

git diff --check
./scripts/test.sh
./scripts/validate.sh
git add .
git commit -m "feat(scope): describe change"
git push origin <branch>

Commit, push, tag, release y publicación son acciones separadas. Los gates verifican; el humano autorizado acepta.
